# Render

Assembles dataset, schema, profile, and chart HTML into finished pages
using Jinja2 templates. This module has no CLI command of its own -- it's
the last step inside `dataforge build`, and is also usable directly.

## Layouts

The dataset preview on the generated `index.html` supports three layouts,
controlled by `dataforge build --layout`:

| Layout | CSS technique | Best for |
|---|---|---|
| `table` (default) | Horizontally scrollable `<table>` with a sticky header and sticky first column | Familiar spreadsheet view; datasets with a manageable column count |
| `cards` | Flexbox (`display: flex; flex-wrap: wrap`), one card per row | Wide datasets (many columns) on any screen size, no scrolling |
| `grid` | CSS Grid (`repeat(auto-fit, minmax(...))`), one card per row | Similar to `cards` but with more even card sizing on wide desktop screens |

## CLI usage (via `build`)

```bash
dataforge build examples/sample_repeaters.csv --out-dir output/repeaters
dataforge build examples/sample_repeaters.csv --out-dir output/repeaters --layout cards
dataforge build examples/sample_repeaters.csv --out-dir output/repeaters --layout grid --chart-x city --chart-y frequency_mhz
```

Output structure (all three layouts produce the same file set, just a
different `index.html` body):

```
output/repeaters/
  index.html       # dataset overview + preview (table/cards/grid per --layout)
  schema.html       # rendered schema table
  charts.html        # embedded chart(s), only written if --chart-x was given
  data/
    repeaters.csv
    repeaters.schema.json
    repeaters.schema.yaml
    repeaters.profile.json
```

## Python API

```python
from dataforge.ingest import load_dataset
from dataforge.schema import infer_schema
from dataforge.profile import generate_profile
from dataforge.export import df_to_html_table, df_to_records
from dataforge.render import build_site, render_page

df = load_dataset("examples/sample_repeaters.csv")
schema = infer_schema(df, dataset_name="repeaters")
profile = generate_profile(df, dataset_name="repeaters")

# Table layout
written = build_site(
    dataset_name="repeaters",
    table_html=df_to_html_table(df),
    schema=schema,
    profile=profile,
    charts=[],
    out_dir="output/repeaters",
    layout="table",
)

# Cards layout requires `records`
written = build_site(
    dataset_name="repeaters",
    table_html=df_to_html_table(df),
    schema=schema,
    profile=profile,
    charts=[],
    out_dir="output/repeaters_cards",
    layout="cards",
    records=df_to_records(df),
)

print(written)   # {'summary': Path(...), 'schema': Path(...)}
```

`render_page(template_name, context)` renders any single template in
`src/dataforge/templates/` directly if you want a custom page instead of
the standard summary/schema/charts trio -- see "Custom templates" below.

## Custom templates

All templates extend `base.html.j2`, which defines the shared page shell,
CSS (including the `.table-scroll`, `.record-cards`, and `.record-card`
classes used by the built-in layouts), and navigation. To add your own
page, drop a new `.j2` file into `src/dataforge/templates/` that extends
`base.html.j2` and call `render_page("your_template.html.j2", context)`.

## Working example: custom PHP-friendly output

Since `render_page` just returns a string, you can write it anywhere --
including as a fragment to `include()` from PHP instead of a full page:

```python
from dataforge.render import render_page

fragment = render_page("chart.html.j2", {"dataset_name": "repeaters", "charts": my_charts})
open("wp-content/themes/mytheme/parts/repeater-charts.php", "w").write(
    "<?php /* Auto-generated by dataforge -- do not edit directly */ ?>\n" + fragment
)
```

## See also

- [Jinja2 template documentation](https://jinja.palletsprojects.com/) -- for template syntax (macros, filters, template inheritance) beyond what the four bundled templates use. dataforge's `_env()` sets `autoescape=True` and `trim_blocks`/`lstrip_blocks=True`; keep that in mind if you add templates with custom whitespace control needs.
